# 03. Implement + UT + Docs

## 项目规则

实现前读取本任务 `_rules/rules/` 下的全部规则文件，并在编码、测试和文档更新中遵守。记录实际读取的路径、每条约束如何落到本次改动，以及与 Core 冲突时的取舍。快照缺失或只有说明文件时写明无额外项目规则。不得改用创建任务之后才修改的 `.wally/rules/`。

## 实际改动与 Plan 差异

## Red → Green → Refactor

逐组关联 Plan 用例，记录各阶段命令、版本、预期失败原因、关键输出与通过数。无需重构或非执行代码的不适用项写依据。

## UT 与增量覆盖率

按项目配置记录代码分类、行/分支门槛、实际增量结果、报告依据、未覆盖代码与回归结果。

## 缺陷回归（适用时）

真实缺陷断言、修复前后证据、最低层级回归与仍待环境验证的边界。

## Docs

受影响的权威文档、实际更新与无需更新的依据。

## 增量 CR

实际读取的项目规则（含本任务 `_rules/rules/`）和语言版本、最终 diff 范围、发现/修复/复核结果、未解决风险。

## 完成结论

TDD、覆盖率、Docs、CR 各项通过/失败/未验证/不适用及依据；适用门禁失败不得 Deploy。

## 知识库证据

按任务绑定的 `core/knowledge.md` 执行本阶段职责。记录实际读取的相关路径、源码核验、缺口、受影响文档及更新/无需更新依据、校验结果；最终 Review 对照完整任务 diff 复查。
